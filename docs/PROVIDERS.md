# Provider verification — 8 September 2026

Text provider update: use **Groq**, `GROQ_API_KEY`, model `openai/gpt-oss-120b`, endpoint `https://api.groq.com/openai/v1`. The existing OpenAI SDK 3.8.0 is used only as the compatible client described in [Groq's official guide](https://console.groq.com/docs/openai); OpenAI credentials are not read by application configuration. The model is in Groq's [production catalog](https://console.groq.com/docs/models); Llama 3.3 is currently listed as enterprise-only there. [Groq local tool calling](https://console.groq.com/docs/tool-use/local-tool-calling) documents forced named tools and streaming. The adapter sends a standard JSON function schema, disables parallel calls, and retains complete-arguments and finish-reason validation. Endpoint/key routing, configuration readiness and stream parsing are tested through fixture HTTP transport. Real Groq inference remains **not run** until a key is configured. The installed LiveKit OpenAI plugin is not used for inference.

Recovery review: a newly initialized worker publishes `connected` before controller recovery so a persisted failed-provider state cannot suppress its own recovery speech. Here `connected` means the LiveKit session and configured provider adapter are initialized; only `active` reflects the SDK speaking event, and neither replaces the credentialed synthesis preflight. Provider and control-transport errors terminate this worker's loop, interrupt output, report their distinct source when the API is reachable, and run bounded cleanup followed by supported `JobContext.shutdown`. API timeouts are not reported as Rime failures. Rime/STT error details are reduced to categories. A fresh worker claims a monotonic `worker_epoch`; every subsequent internal request carries `X-Worker-Epoch`, fencing callbacks and final disconnect notifications from a retiring job.

Same-room recovery needs server-side explicit dispatch. [LiveKit dispatch documentation](https://docs.livekit.io/agents/server/agent-dispatch/) states that access-token agent configuration applies only at room creation and is ignored for an existing room. The authenticated API therefore manages dispatch; browser tokens retain scoped join privileges rather than service credentials. Dispatch, same-room reconnect and worker shutdown were source-verified but remain untested against a real LiveKit service in this environment.

Deepgram keyterms come from the session snapshot's actual inventory names and aliases, deduplicated and capped at 100. Controller-approved `say` calls now retain SDK chat items so `conversation_item_added` can expose the SDK's aligned/forwarded assistant transcript, including truncation on interruption when available. Installed `voice/agent_activity.py::_say_task` adds that item to the originating `SpeechHandle.chat_items` before emitting the session event. The worker matches that exact SDK message/handle identity to the original response and epoch, never to the latest response. These texts are emitted as `delivery_estimate` metrics with `trusted=false`; forwarded text can still overestimate physical hearing, and no such estimate authorizes generic confirmation.

The explicit Rime configuration is `model=coda`, `speaker=astra`, `lang=en`, `sample_rate=24000`, `use_websocket=True`, `segment=bySentence`, `base_url=wss://users-ws.rime.ai`. Do not rely on defaults: the installed plugin defaults to `arcana`, despite the online integration documentation describing Coda. `RimeConfig` supplies each argument explicitly. The installed `_ws_url()` appends `/ws3`; passing a base URL that already contains a path is rejected.

The [public catalog](https://users.rime.ai/data/voices/all-v2.json) was downloaded on 8 September 2026. Its exact schema is model → language → list of voice strings. `coda.eng` contains `astra`; preflight maps configured `en` to catalog `eng` and validates this exact three-way pairing. This confirms catalog presence, not endpoint synthesis. Catalog SHA-256: `3a4146ba98584c54bab9f66e8cf9b04c8d0281a976bcf5d4efc8831e836578dd`. The [voice guidance](https://docs.rime.ai/docs/voices) confirms that language compatibility is voice-specific.

The configured endpoint resolves to `wss://users-ws.rime.ai/ws3`, documented as US West (`us-west-2`). US East is configurable with `RIME_BASE_URL=wss://users-east-ws.rime.ai`. Regional latency has not been measured from a deployed worker; the default is provisional. Run the same synthesis checks from the deployed worker against both documented origins before selecting a measured region. See [regional endpoints](https://docs.rime.ai/docs/regional-endpoints).

The Rime leg uses JSON WebSocket messages carrying base64 PCM, decoded by the plugin into signed 16-bit mono audio at 24 kHz. The separate browser leg is LiveKit WebRTC audio (normally negotiated Opus); verify actual codec statistics in the deployed browser before claiming the negotiated format. It is not the Rime PCM WebSocket. The [Coda WebSocket reference](https://docs.rime.ai/api-reference/coda/websockets-json) documents English/Spanish timestamps, segmentation and context IDs. Context IDs do not implement arbitrary simultaneous generation isolation, and a synthesis `done` is not proof of human hearing.

Installed source inspection: `.venv/lib/python3.13/site-packages/livekit/plugins/rime/tts.py`, methods `TTS._ws_url`, `_close_ws`, `aclose`, and `SynthesizeStream._run`. Streams create fresh context IDs, sentence-tokenize text, flush input, decode chunks and consume timed transcripts. Cancellation cancels send/receive/tokenizer tasks. The Agents `utils/connection_pool.py::connection` catches `BaseException`, removes the cancelled connection, and queues closure; next acquire or pool close drains it. Rime closure sends `eos`, waits at most one second, then closes. It does not send a magic application epoch or guarantee removal of audio already in browser buffers. This implementation uses application identities and stops the speech handle, rather than treating context IDs as correctness fences.

`AgentSession.interrupt(force=True)` and `SpeechHandle.interrupt(force=True)` are installed supported APIs. Agents `voice/agent_activity.py` calls the output's `clear_buffer` during interrupted output; `voice/room_io/_output.py` clears its local audio source. Actual browser audible-stop latency is still unverified. No application-level unmute gate guesses that new text identifies new buffered media. See [LiveKit turn handling](https://docs.livekit.io/agents/logic/turns/).

The worker binds `pickmate-{session_id}` to `worker-{session_id}` using `RoomOptions(participant_identity=...)`; text input is disabled. Deepgram uses explicit `nova-3`, `en-US`, and supported inventory keyterms; Silero VAD drives turns. Input remains active throughout API interpretation and lookup. The installed [Deepgram integration](https://docs.livekit.io/agents/models/stt/deepgram/) signature was checked for `keyterms`. `on_user_turn_completed` submits the final transcript and raises installed `StopResponse`; the worker has no autonomous LLM. The API interpreter owns streaming reasoning and typed intent validation.

Speech onset immediately interrupts locally and enqueues controller onset before any final transcript. Pending control requests suppress scheduling. A 100 ms poll checks current response epoch, task identity and task version, followed by a fresh snapshot just before `say`. While paused, only speech explicitly marked `allow_while_paused` by the controller can play. False interruption recovery goes through the controller; SDK automatic resume is disabled. A separate 1.5-second silence timer handles VAD-only noise during silent lookup, where the SDK has no interrupted speech handle and may emit no false-interruption event; any transcript or newer onset fences that timer. Completion callbacks retain the original response ID. SDK playback completion is sent as `trusted=false`: **generic “yes” cannot authorize a live pick**. Use a self-contained phrase such as “Confirm four red cartons.” This is a deliberate conservative limitation until a tested trustworthy playback boundary exists.

Provider status becomes active on the SDK speaking event. It is never a hardcoded success label. Errors stop speech and preserve API state; there is no alternate TTS. Control API calls time out after five seconds, Rime requests after ten seconds with no automatic synthesis retry, speech handles after 45 seconds, and cleanup after ten seconds. A worker reconnect performs controller recovery. Transport failures are reported by category without embedding exception text or credential values. SDK stage metrics and worker monotonic events are available as proxies; they do not measure physical speaker latency.

Preflight fetches the catalog once, records UTC time, hash, pairing, package versions, non-secret configuration and missing credential names under `evidence/preflight/`. `--catalog-file` accepts an explicitly downloaded catalog and records its source. With a Rime key, it streams two fixed-model/voice bin wording variants and saves real WAV clips plus first-decoded-frame timing; human intelligibility review stays pending. `--live` exits nonzero if any required service credential is missing or synthesis fails. It does not certify STT/LLM/live browser behavior. Offline mode clearly leaves catalog/synthesis unverified. The secret scanner inspects tracked and unignored candidate files, detects configured credential values and selected key patterns, and reports filenames only. It is a bounded safety check, not an exhaustive secret detector. No organizer preflight was supplied; that separate gate remains pending.
